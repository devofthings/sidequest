## Owned CI cancellation #102

Run every CI-driver command in a new process session and retain its owned group through descendant cleanup. SIGINT/SIGTERM must stop all active owned groups with a shared three-second TERM grace followed by KILL, then reap command leaders before worker, cache, and simulator contexts finish unwinding. Never use name-based process killing, target unrelated groups, or erase devices. A signal arriving during command creation is deferred until registration; do not pass blocked termination signals into children. Never call `Popen.wait` inside the signal handler, because an interrupted wait may hold its non-reentrant lock.

After cancellation, reject ordinary commands; allow only the existing explicitly labeled owned `simctl shutdown` and `delete` operations so #114 cleanup can finish. Retain command logs, outcomes, and `cancellation.json`; remove any success manifest and exit unsuccessfully. Repeated handled signals do not interrupt cleanup. Cancellation invalidation runs outside summary output and signal-handler teardown, so a late handled signal cannot retain a success manifest. SIGKILL, power loss, detached/new-session descendants, and external simulator-service processes remain outside this process-group guarantee.

The agent-grill readiness assessment settled these bounded technical choices:

| Question | Kind | Selected answer and evidence | Verification |
| --- | --- | --- | --- |
| Which processes may cancellation stop? | Delegated technical choice | Only new-session groups registered by this `ci-verify.py` invocation; no app or runner-wide matching. | Real isolated tree, resistant descendant, unrelated group, and early-leader-exit regressions in `test-ci.py`. |
| How does threaded native work unwind? | Fact / technical choice | Main-thread handlers signal registered groups before unwinding; command waits reap after the handler returns, avoiding Python's wait-lock deadlock. Existing executor/device contexts retain ownership. | SIGINT/SIGTERM and repeated-signal regressions; actual native interruption and subsequent startup remain required before merge. |
| What survives cancellation? | Accepted existing rule | Failed diagnostics and existing Debug/Release products remain; no successful verification manifest or coverage/publisher change. See [CI.md](../docs/CI.md#owned-command-cancellation-102). | Status/log regressions plus lead-owned exact-head native CI and cancellation probe. |

Offline regressions may observe adopted zombies on macOS: these cannot execute, and the driver reaps its own leaders. A permission failure is suppressed only when a read-only process-group state check proves no live member; failures for live members remain failures.
