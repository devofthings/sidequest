## Implemented ownership and recovery

`GeneratedGameBatch.prepare` uses `@concurrent` value generation with a reproducible SplitMix64 seed. Each batch supplies eight descriptors; replenishment starts with four remaining cards. Production chooses a new session UUID and seed once. Initial cards and each batch shuffle once, preserving appended history. The dedicated Debug route orders seed104 batches for deterministic native checks.

`FeedComposition` retains append-only cards, descriptors, known IDs, and completed pure rule snapshots. These lightweight values grow with the session so revisits preserve identity, configuration, and completed results; total session memory is not constant. Heavy controllers/runtimes and hosted native pages are limited to previous/current/next. Eviction archives completed Sudoku board/selection, Memory rules, solved Chess attempt, or Bubble game/aim/feedback. It permanently retires the old runtime before releasing its adapter. Restoration creates a fresh invisible runtime with the trusted completed attempt identity and binds one new owner. Skipped unfinished cards return to the same frozen challenge. Bubble Replay resets that frozen configuration and removes the old completion if subsequently skipped unfinished.

Each initial candidate rejects duplicate IDs and exact collisions with its prepared games before adoption/save. New batches skip a later sequence if its exact generated ID equals an existing news ID, preserving that story once and moving the sequence forward. No arbitrary news-ID prefix is reserved. A session/request-owned task gates batch results and errors after every suspension; background, modal absence, retirement, or replacement cancels it. A failed current generation retains history and offers an accessible Retry games action. Retrying prepares the same next sequence. Generation never starts play or automatically changes the selected card.

Sudoku transforms a solved grid and considers each of its 16 clues once, removing only uniquely solvable clues. Memory generates exactly two of each of six symbols and freezes the result. Bubble tries at most 16 ceiling-connected configurations; each uses at most 121 actual-physics angle probes. It accepts only a replayed winning shot, with one additional bounded small fallback whose colors/shot sequence vary. This first generator intentionally supplies easy, one-shot-attainable challenges within the existing eight-shot allowance. It introduces no difficulty/scoring selection. Chess positions remain the two validated bundled puzzles, not newly generated positions.

The native pager compares adjacent-window membership as well as selection. It delays window rebuilding/recentering during tracking, drag, deceleration, or a requested animation, then refreshes after settlement. Existing gesture arbitration, accessible navigation, and system Reduce Motion remain applicable.

`NewsImportModel` captures a `NewsReplacementRequest` before its first read/load await. The session verifies the origin before/after async candidate generation. A prepared candidate then acquires a main-actor lease across save and adoption; competing replacement cannot commit during that boundary. Failed/canceled/stale preparation or failed persistence keeps saved news/current feed and releases the lease. After successful durable save, news and feed synchronously adopt without another cancellation check, throw, or suspension. Other finite Debug routes retain their existing contracts and original fictional fixtures. The endless native route uses an isolated `EndlessNewsTests` store and no real captures.
