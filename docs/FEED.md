# Feed presentation contract

Issue #3 implements the host using the [shared card contract](CONTRACT.md) and [coding rules](CODING.md). Feed domain values remain pure Swift. Observable presentation owners run on the main actor and depend inward.

## Composition and interfaces

`FeedSelection(cards:)` retains the ordered deck and bounded selected index. Navigation does not shuffle, drop, or add cards. `FeedController(cards:runtimes:)` receives a runtime for each game card, owns selection and scene/host eligibility, and exposes `selectedCard`, `position`, `count`, `canGoBack`, `canGoForward`, `next()`, `previous()`, `commitPage(at:)`, `setHostAvailable(_:)`, `retire()`, and `setSceneActive(_:)`. Construct the deck through `DeckBuilder` before composition; missing game runtimes are a programmer wiring error.

`GameRuntime(makeAttemptID:)` is a retained observable reference around one private `GameLifecycle`. It exposes read-only `phase` and `isVisible`, plus `setVisible(_:)`, `start()`, `complete(attempt:)`, and `acceptsInput(from:)`. Issue #8 adds `replay() -> Bool` only for the bubble shooter: visible completion replaces this same owner's private lifecycle, delivers reset while preview, then starts a distinct fresh attempt if still visible. Hidden, preview, playing, or duplicate injected identities reject replay. The default attempt factory uses the core default identity; deterministic tests can inject identities. Call `installEffectHandler(_:)` exactly once during composition, before interaction. The handler runs synchronously after each accepted transition. Repeated starts or visibility changes that return no effect call no handler.

Each game controller retains its runtime. App composition retains game controllers by `CardID`; the effect closure captures its controller weakly. Reset invalidates the old token first, cancels delayed work in the controller, then clears rules/selection/feedback. Stop cancels work and keeps the completed result. Game input and every delayed mutation must call `acceptsInput(from:)`, including after suspensions. A disappearing view is never the sole task owner or cancellation path.

`FeedView(controller:gameContent:newsContent:)` receives main-actor closures `(GameCard, GameRuntime) -> AnyView` and `(NewsSnapshot) -> AnyView`. Its preview renders the accessible Tap to play button and consumes the start tap; playing/completed phases render the injected surface. The game closure resolves an already-retained controller; it does not create one. Individual game rules remain outside the host. The concrete runtime avoids adding unused protocols or a dependency-injection framework.

`FeedStartup` retains startup state and awaits the explicitly off-UI Chess fixture loader once before publishing the feed. Its root structured task and loading identity reject canceled or late completions. `FeedComposition(chessPuzzles:)` synchronously retains decoded immutable fixtures without file I/O; both Chess cards and generic replacement reuse that cache. A loaded view does not reload or reshuffle its session. Import integration #9 can construct replacement candidates from the same cache before committing disk changes. See [Chess loading](CHESS.md#presentation-contract).

The current composition supplies playable [mini Sudoku](SUDOKU.md), [memory pairs](MEMORY.md), [chess puzzles](CHESS.md), a [bubble shooter](BUBBLES.md), and sourced fictional news using the shared unwrapped `NewsCardContent`; it retains source/date/sample labels instead of duplicating news presentation. App-owned `ComposedGame` resolves each retained concrete controller and its runtime without teaching the feed about individual rules. A validated Sudoku fixture is selected once during composition; rendering and restarting the same card do not select another puzzle. Memory creates a fresh shuffled board on each explicit start; its controller owns delayed mismatch resolution and gates every result through the same runtime. Chess maps its two stable cards to original White/Black bundled fixtures and retains separate controllers. The six-card generic feed/replacement tests and four-card games-only harness retain provisional surfaces independent of rules. Bubble shooter retains its bounded challenge controller, cancellable shot work, and completed-visible replay. Imported news connects through these closures in #9. `-sidequest-news-preview` preserves the standalone Debug library/import surface until #9 connects saved imports to the normal feed. Bubble-shooter replay uses #8's compatible completed-visible runtime extension; the bubble controller owns its action and fresh board. The host adds no replay action to other games.

The DEBUG-only `-sidequest-feed-test` route intentionally supplies generic demos for every game kind to keep the host's lifecycle checks independent of game rules. Normal/Release Sudoku cards use the actual Sudoku adapter. The separate `-sidequest-sudoku-test` route selects Sudoku first, the first validated fixture, and one news card for deterministic gameplay checks; it is not a production puzzle-selection setting. The DEBUG-only `-sidequest-memory-fixtures` route selects Memory first, adjacent original pairs, one news card, and a two-second mismatch delay for inspection. Normal/Release Memory uses shuffled boards and a 700 ms delay. Feed selection, skip/reset ordering, and completion retention are unchanged.

## Navigation and eligibility

Issue #87 supersedes the rail from #3. A bounded native UIKit pager hosts at most the previous/current/next card. Cards follow the finger; native paging supplies distance/velocity snapping. Short drags return to the current card. The compact Feed navigation menu requests Previous card/Next card through that same pager. Position/end feedback and explicit empty states remain; no automatic movement or reshuffling occurs.

Selection commits only at the end of deceleration, an immediate settled drag, or the end of a requested animation. Programmatic navigation under system Reduce Motion settles without animation. Finger tracking remains native. Neighbor pages have input and accessibility disabled; rendering a neighbor never starts its runtime. A canceled drag commits nothing and keeps the current attempt. A committed skip invalidates the old token and delivers reset before making the new card eligible. Completion persists across revisits.

Each hosted page owns one native vertical content scroller. News injects `NewsCardContent`; standalone library `NewsCardView` supplies its own wrapper. Game views stay unwrapped. When content can move in the drag's direction, its scroller owns the gesture. An outward gesture beginning at an already-reached top/bottom edge pages; reaching an edge during a drag requires another outward gesture. Both owned recognizers reject predominantly horizontal drags, and a slider's tracking region blocks paging. The child recognizer requires the parent to fail, with no reverse requirement or replaced UIKit delegate.

The adapter keeps native page height fixed to its viewport, uses proper child-controller containment, forwards public Dynamic Type/color/locale/layout-direction values into hosting roots, and hides neighboring accessibility trees. Resizing and eligibility loss recenter the committed card. Dismantling stops the obsolete adapter. `FeedController.canNavigate` combines active scene, available host, and permanent retirement. Inactive/background/modal hosts reset unfinished play once; returning requires a new start. Later #9 uses host availability and retirement for library presentation and deliberate imported-session replacement. A retired controller cannot be reactivated by an old scene callback. Requests are bound to their originating controller identity. On replacement, `FeedView` clears obsolete request state and applies the current scene phase even when the outer view identity stays the same; the fresh native pager independently rejects an old-session request before moving.
