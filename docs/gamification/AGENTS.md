# Gamification proposal ownership

Before changing phase-two result metrics, ranking eligibility, displayed identity, or score credibility, read [the proposal](README.md) and [issue #19](https://github.com/devofthings/sidequest/issues/19). Its concrete mechanics and screen sketches are **proposed**, not implementation authorization. Record an explicit owner selection before creating implementation work under those rules.

Keep factual current-game behavior separate from proposed instrumentation. Preserve explicit start, unfinished skip/reset, completed revisits, and game-owned replay. The first MVP remains unchanged. Link backend requirements to [#18](https://github.com/devofthings/sidequest/issues/18) and visual implementation to [#13](https://github.com/devofthings/sidequest/issues/13); neither a provider recommendation nor these sketches activates a service.

Maintain one authoritative metric definition in this folder. When a challenge or rules version changes, review comparability rather than combining incompatible results. Personal, self-reported shared, and server-validated results retain distinct credibility labels. These are proposed phase-two rules pending the owner's decision.
