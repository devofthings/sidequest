## Implemented boundaries

`FeedNewsCard` carries an appearance ID and the unchanged snapshot. `FeedNewsCadence` prepares additions plus its next partial game count, pool cursor, and ordinal. `FeedComposition` validates all actual appearance/game IDs before changing descriptors, cadence, known IDs, or history. Canceled, stale, failed, or rejected batches keep the prior cadence; retries continue the same sequence and story order. Source IDs can resemble game IDs without colliding with their distinct news appearances. The finite constructor keeps its exact legacy reserved-ID checks.

`DemoNewsLoader` reads the separate bundled resource off the UI actor through the existing importer. `NewsImportModel.loadResolvedSnapshots` shares one nil-only policy between startup and retry. `LocalNewsStore.load` inspects path components and preserves invalid, inaccessible, or dangling paths as errors. Confirmed absence loads demos without a write; importing an empty document keeps news disabled across relaunch. Original successful import bytes and the exclusive save/adoption lease remain unchanged.

The pager exposes `feed.selected.<CardID>` as identifier metadata for its settled selected card and labels the scroll surface with the headline or game title. No numeric position element remains in any feed route. Native test helpers check this exact committed identity; their immediate success paths use the same predicate as the bounded wait. Human speech does not contain raw IDs. All finite gesture/game/import checks retain their original behavior assertions.
