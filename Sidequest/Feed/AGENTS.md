# Feed ownership

`Domain` owns deck/session behavior; presentation consumes domain values and shared lifecycle effects. See [CONTRACT.md](../../docs/CONTRACT.md) and [source ownership](../../docs/STRUCTURE.md).

Build and store a shuffled deck once per deliberate session creation using injected randomness. Rendering never reshuffles it. Reject duplicate card IDs rather than dropping content; multiple cards of the same game kind are valid when their IDs differ. Visibility means the host's selected card, not SwiftUI appearance. Feed presentation and background handling follow issue #3, not the contract's sample launch view.

Issue #87 supersedes the dedicated swipe rail. Full-card vertical paging is a UIKit adapter with native distance/velocity snapping and at most previous/current/next hosted SwiftUI pages. Commit selection only after native scrolling settles. Short/canceled drags keep the current attempt; neighboring pages remain visually rendered but input- and accessibility-ineligible. Compact navigation-menu actions request a settled page through the same adapter. Bounds and the end message remain explicit.

Each hosted card has one owned vertical content scroller. Use unwrapped news content and plain game content. A drag beginning within available content range scrolls the card; a subsequent outward drag beginning at its top/bottom edge pages. Reaching an edge during a content drag keeps that gesture content-owned. Both recognizers reject horizontal drags; the parent defers when an owned slider starts tracking. Keep the one-way child-pan failure requirement and UIKit's internal gesture delegates. See [FEED.md](../../docs/FEED.md#navigation-and-eligibility) before changing arbitration or hosting.

`FeedController` owns selection, scene/host eligibility, and permanent session retirement, using retained `GameRuntime` references supplied by composition. Invalidate the previous card and deliver reset synchronously before enabling another card. An inactive/background scene makes every runtime invisible and resets unfinished attempts once; returning activates the selected preview without starting it. Completed results remain retained. Views render phase and send explicit actions; they never copy lifecycle values or own game rules/tasks.

`FeedView(controller:gameContent:newsContent:)` accepts main-actor render closures `(GameCard, GameRuntime) -> AnyView` and `(NewsSnapshot) -> AnyView`. Composition provides a runtime for every game ID before exposing the feed. Rendering a closure cannot create a controller, reshape the deck, or mutate lifecycle. See [feed adapter contract](../../docs/FEED.md) for ownership, effect ordering, and downstream integration.

Forward public Dynamic Type, color scheme, locale, and layout-direction values into separate hosting roots. Reduce Motion comes from the system and makes requested navigation nonanimated; direct finger tracking remains native. Keep start, compact navigation, and overflowing card controls reachable at the largest text size. Preserve proper child-controller containment and stop the obsolete pager when its controller is replaced.
