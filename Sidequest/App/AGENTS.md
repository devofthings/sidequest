# App composition

`SidequestApp` is the entry point and composition root. The feed uses standard SwiftUI typography, semantic colors, and an accessible heading. Store the fictional sample deck once in retained composition via `SampleSession.make()`; rendering must not reshuffle it. Follow the [card contract](../../docs/CONTRACT.md) for explicit start/reset/completion. Inject concrete news/game adapters here as their owning issues establish consumers. Follow [application boundaries](../AGENTS.md).

Use iOS 17.0 as the minimum deployment target: the selected SwiftUI foundation and intended feed need no newer API. Runtime testing on a newer simulator does not establish runtime compatibility on every supported OS or a physical device. Keep personal signing teams and account configuration local; see [INSTALL.md](../../docs/INSTALL.md).

`FoundationView` preserves the standalone Debug manual-news preview/import sheet from #4 until #9 connects imports to the normal feed. Its news state belongs to `NewsImportModel`; see [news guidance](../News/AGENTS.md). This preview neither starts games nor changes shuffle semantics.

Issue #3 retains `FeedComposition` in app state. It owns the stored sample deck, feed controller, and one game controller/runtime per stable card ID; render closures only read those retained owners. Provisional game surfaces are explicitly labeled demos until #5–#8/#9 connect actual game rules. They verify start/input/completion/reset without implementing scoring or a new game.

Render fictional session news through the shared unwrapped `NewsCardContent` from #4/#87 so provenance, dates, original links, and accessibility share one owner. Saved-import session composition remains #9; keep the standalone Debug library route until that integration is verified.

Debug-only launch arguments select deterministic feed order (`-sidequest-feed-test`), an empty deck (`-sidequest-feed-empty`), games-only content (`-sidequest-feed-games-only`), or the largest accessibility text size (`-sidequest-large-text`) for running-app tests. `-sidequest-news-preview` preserves the foundation view for the separately owned news tests. Release builds ignore all these test routes. Normal launch uses the once-shuffled sample session and system text size; no user-facing test setting or auto-reshuffle is introduced.

Issue #5 adds the concrete `ComposedGame` enum at this composition boundary: it retains each game's controller/runtime and returns its view through the existing feed render closure. Normal Sudoku cards now use `SudokuController`; other adapters replace their provisional cases in their owning issues. The lead owns central composition edits while game agents own their folders. Keep the DEBUG generic feed-test harness separate from real gameplay routes so lifecycle tests remain independent of game rules. The Sudoku test route uses a fixed puzzle and an adjacent news card; Release ignores it. Construction errors remain visible through the session failure surface.

For Sudoku, select one validated fixture once when composing the card, with random fixture selection in production and fixture zero for `-sidequest-sudoku-test`. Retain that fixture across resets so rendering or skipping does not change the puzzle. Keep game-specific controllers in `ComposedGame`; the feed remains independent of their rule types.

Issue #6 adds `ComposedGame.memory`, retaining one `MemoryController` and its runtime per card. Normal/Release starts create a six-pair shuffled board through the controller's injected factory, and production mismatch resolution uses 700 ms. The DEBUG-only `-sidequest-memory-fixtures` route selects Memory first plus one news card, adjacent original pairs in symbol order, and a two-second mismatch delay so running-app tests can inspect the revealed state before reset. The generic `-sidequest-feed-test` harness continues to use demos; the feed never imports Memory rules. See [Memory guidance](../Games/Memory/AGENTS.md) for task ownership, cancellation, and accessibility decisions.

Issue #87 replaces the rail with the production native pager in every feed route, including deterministic real-game fixtures. Hosted views resolve retained owners and receive explicit public environment values; composition still shuffles only at deliberate session creation. Imported-news session replacement remains #9 and must retire the old feed controller before exposing the new one.

The DEBUG-only `-sidequest-feed-replacement-test` route retains the same outer FeedView identity and explicitly replaces and retires its fictional generic session for the #87 regression. The fixture button and demo selection are excluded from Release. It establishes activation and old-request rejection under unchanged scene phase; actual imported-news replacement remains #9.
Issue #7 replaces the production chess demo with two stable cards: `sample-game-chess-white` maps to `queen-corner-white`, and `sample-game-chess-black` maps to `queen-corner-black` in the validated bundled fixture set. Retain each `ChessController(puzzle:runtime:)` separately in `ComposedGame` and render `ChessPuzzleView(controller:)`; missing fixtures remain visible composition failures. The normal sample session contains both original chess puzzles and shuffles the complete seven-card deck once. Keep the DEBUG generic feed-test six-card and games-only four-card harnesses on provisional controllers by requesting the original single-card-per-kind sample membership; those test routes do not represent production gameplay. Both chess fixture routes select the requested color first plus one fictional news card, and Release ignores them. Root composition chooses cards; the chess adapter owns all puzzle and coordinate behavior. See [CHESS.md](../../docs/CHESS.md).
