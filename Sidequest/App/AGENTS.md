# App composition

`SidequestApp` owns one retained `FeedSessionState` and one `NewsImportModel`. The model's prepare closure may retain the coordinator; the coordinator never retains the model or a stored closure capturing it. Its startup method receives the model transiently. Follow [coding rules](../../docs/CODING.md), [card contract](../../docs/CONTRACT.md), and [application boundaries](../AGENTS.md).

## Integration #9 decisions

Evolve the existing startup owner into the single session coordinator rather than adding a competing startup/library/deck state machine. Load immutable Chess fixtures through its async `@concurrent` adapter and saved news through the side-effect-free storage read. Check cancellation and the current loading UUID on success and error paths before constructing a deck or adopting news. Canceled or stale results cannot publish, erase current news, or become a corrupt-news fallback. Rendering, sheet reopening, and completed startup never reload or reshuffle.

`FeedComposition(news:chessPuzzles:)` throws and constructs five real game cards: Sudoku, Memory, bubble shooter, and separate White/Black Chess cards. Validate all news IDs against the exact five reserved IDs and validate full composition before saving an import. Similar IDs, including the old single Chess demo ID, are permitted. Shuffle once per deliberate successful session creation. Retain one concrete controller/runtime per stable ID and the immutable Chess fixture cache. The feed never inspects game rules; `ComposedGame` owns concrete adapters. Release has no placeholder case or fictional-news fallback.

Missing/empty saved news yields real games only. Corrupt/unavailable news yields real games plus a retryable library error and leaves damaged bytes intact. Missing game fixtures yield an accessible startup failure with Retry, without publishing a fabricated feed. Initial loading disables the library; initial candidate construction finishes before synchronous news adoption and ready publication.

News import prepares the entire inactive candidate synchronously from cached fixtures before atomic persistence. The returned commit cannot throw or suspend: retire the previous controller, apply CURRENT modal availability to the candidate, and publish it. No cancellation check follows successful durable save. The model and deck update in one main-actor turn. Opening the library synchronously makes the host unavailable and cancels unfinished work; reopening/canceling preserves order, position, and completed results. Existing `FeedController` retains scene eligibility and permanent retirement; background/foreground cannot override modal absence or reactivate old sessions. Existing `FeedView` applies current scene phase on controller replacement and rejects old navigation requests.

Normal production uses private imported English snapshots and a once-shuffled real-game deck. The accessible 44-point News button opens the retained model in a library with automatic restoration disabled; startup owns the initial restore. Shared unwrapped `NewsCardContent` stays within the pager's single owned content scroller. NewsLibrary's standalone Debug preview may restore its own samples under the explicit legacy fixture flag.

## Debug verification routes

Keep generic `-sidequest-feed-test`, `-sidequest-feed-games-only`, and `-sidequest-feed-replacement-test` on six fictional cards/four demos (games-only four). Deterministic Sudoku, Memory, White/Black Chess, and Bubble fixture routes retain their original adjacent fictional-news membership; the generic same-view replacement button is Debug only. `SampleSession.make`, `PlaceholderGameController`, and `FoundationView` are compiled only in Debug. Normal launch without fixture flags never creates fictional news.

`-sidequest-integration-fixtures` uses the production constructor, five real game IDs, original fictional files under Documents/Sidequest Fixtures, stable isolated Application Support/IntegrationNewsTests persistence, and deterministic sorted order. `-sidequest-integration-reset` deletes only that owned test store at initial setup, never normal captures. Native Files selection exercises valid, empty, malformed, and exact reserved-ID input; it does not bypass validation or persistence. Debug-only file sharing exposes Documents to the picker; Release has no file-sharing keys or fixture/reset implementation. Fixture file I/O is `@concurrent` away from the UI actor. Integration Memory uses adjacent original pairs and a two-second mismatch delay. Bubble's optional `-sidequest-bubble-slow-shot` uses a six-second flight to expose reset boundaries. `-sidequest-large-text` exercises the largest accessibility category; actual Reduce Motion is changed/restored through native Settings. Release ignores all test arguments.

Select and retain Sudoku fixtures once at construction; skips reset the same puzzle. Memory owns its mismatch task and board factory; Chess owns validated original positions and coordinate input; Bubble owns swept collision, bounded shots, animation, and Replay. Main composition creates adapters once, never in render closures. Preserve minimum iOS17 and explicit actor boundaries. Simulator checks on iOS27 do not establish device/iOS17/VoiceOver operation; signing stays local under [INSTALL.md](../../docs/INSTALL.md).
